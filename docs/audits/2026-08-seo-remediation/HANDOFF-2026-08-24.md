### Important #3 — REDIRECT_ENTRIES loop drops query strings
The plan's own Global Constraint #3 says query strings must survive every hop "matching every existing redirect rule in the file" — that claim is false for the shared static-entry loop. `proxy.ts` around the `REDIRECT_ENTRIES` dispatch (search for `for (const entry of REDIRECT_ENTRIES)`) does:
```ts
return withCsp(NextResponse.redirect(new URL(entry.to, request.url), 301), nonce)
```
— no `url.search = request.nextUrl.search`. Affects all 26 static entries including the new `/bariatricproducts` row. Also silently drops ad-attribution params (`captureAttribution()` only runs on the pass-through branch). **Fix:** build the URL, set `.search` from `request.nextUrl.search`, then redirect — same pattern already used by every other redirect branch in the file. Add a regression test (e.g. extend the `/bariatricproducts` test, or add one general test asserting query preservation across a sample of `REDIRECT_ENTRIES` rows) — this closes it for all 26 rows at once.

All 6 currently ride along in the same www-noindex issue in the CSV data, so can't fully distinguish "also broken on canonical host" from "only visible because of the noindex bug" without a fresh crawl post-Bilal-fix.
- **Sitemap** (`lib/seo/sitemap.ts`): flat single sitemap, not an index+child-sharded structure (plan wants sharding). No `/products/`, `/collections/`, or query-string URLs leak in — that part is already correct.
- **robots.txt** (`lib/seo/robots-config.ts`): `/checkout` is not disallowed (looks like an oversight — `/search` is deliberately allowed with a documented rationale, `/checkout` has none). No filter/sort/facet query-param disallow rules exist at all.
- **Structured data**: all 12 `Notice-Structured_data_has_Google_rich_results_validation_error.csv` errors cluster on pharmacy/HRT-clinic products. Hypothesis (not confirmed — CSV gives no field-level detail): `components/schema/ProductSchema.tsx` may emit an `Offer` with an unusable/zero price for these controlled-substance-adjacent products instead of omitting it, which is what Google's Rich Results validator would reject. Needs a live Rich Results Test run against one URL to confirm.
- **IndexNow**: does not exist anywhere in the repo. Plan's P1-07 entirely unaddressed.
- **2 legacy Shopify routes need redirects**: `/collections/all` (1 inlink, should probably → `/categories`) and `/a/sitemap-tools/sitemap` (8,128 inlinks — Shopify's own theme sitemap page) — both currently return 200 but aren't served by this app and aren't in the sitemap.
